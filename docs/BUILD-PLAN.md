# Completion plan — September 5, 2026

The owner requested a complete build as far as the available environment permits, unit and integration tests, a professional developer handoff, advisor training, a full manual, a walkthrough, and realistic client output examples. This extends the initial foundation release. It does not supply customer credentials or establish independent production acceptance.

## Delivery work

1. Graph readability, meaningful organization/duty view, and layout regressions.
2. Audit all 90 supplied requirements against code, test evidence, and external dependencies.
3. Finish the advisor journey: bounded kickoff, evidence review, work/duty and workflow models, measurement and outcome reviews, client reporting, and delivery.
4. Add supported local service adapters and operational controls: durable jobs, bounded graph queries/repair, migration tracking, backup/recovery, health, and security regressions.
5. Validate the integrated product, accessibility and responsive behavior, clean installation, performance workload, dependencies, and CI.
6. Deliver a searchable in-app help center and portable documentation: explainer, walkthrough, advisor playbook, full user manual, training workbook and answers, sample client reports/packages, and technical runbooks.
7. Reconcile every requirement with actual implementation/test evidence and document the exact infrastructure/customer dependencies remaining.

## Verification rules

- Test real database/API behavior separately from pure unit logic and browser interactions.
- Never label a simulated provider response, unconfigured integration, or draft approval as a live execution result.
- Keep synthetic training data and example outputs visibly labeled.
- Preserve the original source files and existing company records.
- Only publish public-safe product code and authored documentation; the supplied commercial handoff remains outside this public repository.

The final release notes and requirement matrix supersede this working plan as the delivery record.
