# Repository working instructions

For a continuation or another computer, read `START-HERE.md` and `docs/NEXT-STEPS.md` before choosing work. They distinguish current decisions from older brainstorms.

Read `README.md` and `CONTRIBUTING.md` before making changes.

The owner requires **every change to update both `README.md` and `DEVLOG.md` in the same change set**, including documentation-only changes. Keep the README concise and current; add a dated development-log entry explaining what changed, why, validation performed, and outstanding limitations or setup. Group related edits into one logical entry. Update affected reference/wiki/help pages as needed.

Preserve unrelated work. Never include secrets, private client evidence or personal lead details in documentation. Report local tests, CI, deployment and real-world acceptance separately; never invent verification results.
